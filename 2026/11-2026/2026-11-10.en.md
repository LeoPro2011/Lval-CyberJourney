### Concepts covered

- **Hash function:** transforms input data of any size into a fixed-size digest (hash value). The same input produces the same digest; recovering the original input from the digest should be computationally impractical.
- **Avalanche effect:** a tiny change in the input should cause a substantial change in the resulting digest.
- **Collision:** two different inputs produce the same digest. Collisions are theoretically unavoidable because the set of possible inputs is larger than the set of possible outputs.
- **Digest sizes:** MD5 produces 128 bits (16 bytes), SHA-1 160 bits (20 bytes), and SHA-256 256 bits (32 bytes). MD5 and SHA-1 are no longer considered secure against collision attacks.
- **Hashing in authentication:** systems should not store passwords in plaintext. Instead, they store a suitable password hash and compare it during login.
- **Salt:** a random value unique to each password, added before hashing. It prevents direct reuse of precomputed rainbow tables and ensures identical passwords do not automatically produce identical stored hashes.
- **Password storage:** dedicated, deliberately expensive functions such as Argon2, scrypt, bcrypt or PBKDF2 are preferable to fast general-purpose hashes such as MD5 or SHA-256.
- **Hash identification and cracking:** tools such as `hashid` help identify formats; Hashcat and John the Ripper can test candidate passwords, for example from a wordlist. This is candidate testing, not hash decryption.
- **File integrity:** comparing a locally calculated digest, for example with `sha256sum`, against a trusted reference digest can reveal modification or corruption.
- **HMAC:** a mechanism combining a secret key and a hash function to verify a message's integrity and authenticity.

### Key takeaway

Hashing must not be confused with encryption or encoding. Encryption is designed to be reversible with a key; encoding represents data in another form; hashing produces a fixed-size digest with no normal mechanism for recovering the original input.

The room connects cryptography with password security and integrity checking. It also highlights that a hash alone does not guarantee a file's authenticity: the reference digest itself must come from a trusted source.
