## TryHackMe: Corridor — IDOR and predictable identifiers

I also completed the [**Corridor**](https://tryhackme.com/room/corridor) room. The Python-based website presents several doors that lead to URLs containing hexadecimal strings that look like hashes.

By observing the URLs, I noticed that these values corresponded to sequential numbers: they are **MD5 hashes of predictable numeric identifiers**. I tested different values by generating their hashes and replacing the corresponding part of the URL. The value **0**, which is not represented by the visible doors, leads to a hidden resource containing the flag.

This demonstrates an **IDOR (Insecure Direct Object Reference)** vulnerability: hashing an identifier does not protect a resource when the original identifier remains predictable and the server does not properly enforce authorization. An identifier being difficult to read is not an access-control mechanism.

## TryHackMe: Agent T — PHP backdoor and command execution

I completed the [**Agent T**](https://tryhackme.com/room/agentt) room. The website displayed a fake administration dashboard, with broken links and 404 errors. Instead of trusting the interface, I inspected the HTTP responses and their headers. A server header revealed an unusual version: **PHP 8.1.0-dev**.

This development version is associated with a known backdoor: a specific HTTP header, **`User-Agentt`** (with two “t” characters), allowed PHP code to be evaluated on the server. Since the browser did not make it easy to craft the required request, I used **`curl`** to send this custom header with the PHP command `system('cat /flag.txt')`. The server returned the file contents within the HTML response; I added **`grep`** to the command to isolate the line containing the flag.

### Summary
- **Agent T: completed** (+1 room)
- Practiced: HTTP-header inspection, identification of a vulnerable/compromised version, custom HTTP requests with `curl`, remote command execution (RCE), and filtering with `grep`
- **Streak:** +1 progress according to my personal tracking

This room demonstrates why inspecting HTTP response metadata matters: it can reveal details about the technology stack and guide an investigation. In this case, the issue came from a backdoor in a specific PHP version, not from the visible dashboard.
