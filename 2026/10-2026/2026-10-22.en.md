## 22 October 2026 — PHP vulnerability and Active Directory discovery

I made an initial exploration of **Active Directory**, then completed a TryHackMe room about a recently disclosed PHP vulnerability.

### Understanding session.upload_progress

I studied PHP's `session.upload_progress` mechanism, which tracks file-upload progress. Depending on configuration, processing a multipart POST request containing the `PHP_SESSION_UPLOAD_PROGRESS` field and a file part can write progress data to `$_SESSION` before the application script executes.

The room's diagram outlines the general sequence: request-body parsing, PHP request initialization (`RINIT`), and then script execution. This highlights that some processing happens before the first line of application code and, in the scenario described, may not require application login.

### The memory-management bug

The room describes an issue involving PHP's *bailout* mechanism and `longjmp`, used to interrupt execution and return to a recovery point after certain errors. The scenario involves an upload-limit failure and a timing issue during error handling and memory cleanup: a pointer may remain referenced after its associated memory region has already been freed.

Depending on the exact execution path, this can leave a dangling pointer and lead to invalid memory access. I want to revisit the CWE classifications associated with this class of bug later.

**Terminology note:** CWE-824 means *Access of Uninitialized Pointer*. If the issue is specifically use of a pointer to already-freed memory, CWE-416 (*Use After Free*) may be a better fit. The exact classification depends on the vulnerability's technical details, so I am not treating it as confirmed.

### Key takeaways

- PHP request lifecycle: multipart POST, `RINIT`, script execution
- `session.upload_progress` and writes to `$_SESSION`
- *Bailout*, `longjmp`, and error recovery
- Memory lifetime, dangling pointers, and use-after-free bugs
- Initial exploration of Active Directory

This room helped me understand how request processing and memory-management errors inside a runtime can have security implications.
